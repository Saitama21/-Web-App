# Хочу v1.1.0 — Multi-account

Личный журнал желаний и покупок с отдельными аккаунтами для друзей и админ-панелью владельца.

## Что нового в 1.1.0

- У каждого пользователя **свой логин, пароль и отдельный список желаний**.
- Пользователь не может увидеть товары другого пользователя.
- Регистрация только через **одноразовую/ограниченную ссылку-приглашение**.
- Даже после приглашения заявка должна быть **одобрена администратором**.
- Администратор видит:
  - новые заявки;
  - список пользователей;
  - активные/заблокированные аккаунты;
  - количество хотелок и накопления по пользователям;
  - запросы на восстановление пароля.
- Администратор может:
  - одобрить или отклонить заявку;
  - создать приглашение;
  - заблокировать/разблокировать пользователя;
  - удалить пользователя вместе с его данными;
  - создать одноразовую ссылку для сброса пароля.
- **Пароли администратору не показываются.** Они хранятся как `scrypt`-хеш с уникальной солью.
- Ссылки сброса пароля действуют 30 минут и хранятся в базе только в виде SHA-256 хеша.
- Сессии хранятся серверно; блокировка пользователя сразу завершает его активные сессии.
- Старые покупки из v1.0.x при миграции автоматически привязываются к первому администратору.

## Логика регистрации

1. Администратор входит в «Хочу».
2. Открывает **Администрирование → Создать приглашение**.
3. Получает ссылку и отправляет её другу.
4. Друг открывает ссылку, придумывает:
   - имя;
   - логин;
   - email;
   - пароль.
5. В админ-панели появляется заявка.
6. Администратор нажимает **Одобрить**.
7. Друг входит по своему логину/email и паролю.
8. Его список полностью отделён от остальных пользователей.

## Восстановление пароля

1. Пользователь нажимает **Забыли пароль?**.
2. Указывает логин или email.
3. В админ-панели появляется запрос.
4. Администратор нажимает **Создать ссылку**.
5. Отправляет ссылку пользователю любым удобным способом.
6. Пользователь сам задаёт новый пароль.
7. Все старые сессии этого аккаунта автоматически завершаются.

Администратор **никогда не получает и не видит новый пароль**.

# Обновление с v1.0.2 на Railway

Перед первым запуском v1.1.0 желательно добавить в Variables приложения:

```env
ADMIN_NAME=Иван
ADMIN_USERNAME=ivan
ADMIN_EMAIL=your@email.com
ADMIN_PASSWORD=придумай_надёжный_пароль
```

Если у тебя уже есть `APP_PASSWORD` из старой версии, `ADMIN_PASSWORD` можно временно не задавать: при первой миграции он используется как пароль первого администратора.

**Важно:** `ADMIN_USERNAME` / `ADMIN_EMAIL` используются при создании первого администратора. Лучше установить их **до первого деплоя v1.1.0**.

`DATABASE_URL` Railway предоставляет автоматически при подключённом PostgreSQL.

## Деплой

1. Распакуй архив.
2. Замени файлы старого репозитория содержимым v1.1.0.
3. Commit → Push в GitHub Desktop.
4. Railway автоматически пересоберёт сервис.
5. Открой:

```text
https://ТВОЙ-ДОМЕН/api/health
```

Ожидаемый ответ:

```json
{
  "ok": true,
  "app": "Хочу",
  "version": "1.1.0",
  "database": "postgresql",
  "adminReady": true
}
```

6. Войди в приложение по `ADMIN_USERNAME` (или `ADMIN_EMAIL`) и `ADMIN_PASSWORD`.

## Миграция данных

Миграция выполняется автоматически при старте:

- создаются таблицы пользователей, сессий, приглашений, заявок и сброса паролей;
- в `wishlist_items` добавляется `user_id`;
- все старые записи, у которых ещё нет владельца, присваиваются первому администратору.

Удалять PostgreSQL или создавать новую базу **не нужно**.

## Безопасность

Реализовано:

- scrypt для паролей;
- уникальная соль на каждый пароль;
- HttpOnly session cookie;
- Secure cookie на Railway/production;
- SameSite=Lax;
- серверные сессии с истечением;
- проверка статуса пользователя на каждом запросе;
- изоляция wishlist по `user_id` на сервере;
- одноразовые reset-токены;
- invite-токены в БД хранятся только как хеш;
- базовый rate limit для входа, заявок и восстановления;
- same-origin проверка изменяющих API-запросов;
- журнал административных действий в БД.

### Важное ограничение v1.1.0

Автоматической отправки email пока нет. При восстановлении администратор копирует одноразовую ссылку и отправляет её пользователю вручную, например в Telegram/Signal/iMessage.

Это намеренно: не нужно подключать сторонний почтовый сервис и хранить дополнительные API-ключи.

## Локальный запуск

Нужен Node.js 20+.

```bash
npm install
ADMIN_NAME=Иван \
ADMIN_USERNAME=ivan \
ADMIN_EMAIL=ivan@example.com \
ADMIN_PASSWORD='your-password' \
npm start
```

Без PostgreSQL приложение запускается в memory-mode только для разработки; данные пропадут после перезапуска.

## Файлы

- `server.js` — API, авторизация, пользователи, PostgreSQL, парсер магазинов.
